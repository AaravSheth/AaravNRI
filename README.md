# AaravNRI

Analyses a resume PDF against the published entry requirements of graduate
information-security programmes and reports a **fit band** with the reasoning
behind it.

## Why bands, not percentages

AaravNRI does not output "72% chance of admission", and this is deliberate.

Universities do not publish applicant-level outcome data. Without it, no
calibrated admission probability can be computed from a resume. A percentage
generated by a language model would be fluent, confident and meaningless — and
users would make expensive decisions on it.

Instead, every profile is compared against each programme's own published
minimums, and the result is one of four bands:

| Band | Meaning |
|------|---------|
| **Safe** | Clears every published minimum comfortably, at a programme admitting a large share of applicants |
| **Match** | Clears every published minimum, but the programme is selective |
| **Reach** | A required value is missing, or falls short of the published minimum |
| **Below minimums** | A published minimum is missed outright |

Scoring is arithmetic, in `lib/match/score.ts`. No model is involved in the
judgement. The model's only role is reading structured values out of the
resume; every verdict traces to a requirement with a `source_url` and a
`last_verified_on` date.

## Security design

Resume PDFs are untrusted files containing personal data, submitted by
strangers, whose text flows into a model prompt. Each of those facts is handled
explicitly.

**PII never reaches the model provider.** Names, emails, phone numbers,
addresses and identity numbers are replaced with stable tokens before the text
leaves the server (`lib/security/redact.ts`). Programme fit depends on degrees,
grades and scores — none of which require knowing who the candidate is. The
mapping is request-scoped and never persisted. `extractProfile` asserts the
text is clean before the network call and throws if it is not, so a redaction
regression fails closed.

**Uploads are validated on raw bytes** before any parser touches them
(`lib/security/pdf-validate.ts`): magic-byte sniffing rather than trusting the
filename or MIME type, size and page caps, EOF-marker check for truncation, and
outright rejection of encrypted PDFs, embedded JavaScript, launch actions,
auto-run actions, file attachments and declared decompression bombs. Hyperlinks
are permitted with a warning, since almost every real resume has one.

**Prompt injection is handled on both sides.** Resume text is wrapped in a
per-request random delimiter that content inside the document cannot guess or
close, under a system prompt that states the delimited text is data. Output must
satisfy a Zod schema; anything off-schema is rejected rather than rendered.
Separately, `lib/security/injection-scan.ts` detects instruction-shaped text and
text hidden from human readers — invisible render mode, white-on-white fill,
sub-2pt fonts. A hit is surfaced and logged for review; it never silently alters
the score, because a false positive would penalise an honest applicant.

**Storage is minimal.** The PDF is never written to disk or object storage and
the resume text is never persisted. Only the extracted profile and the scored
results are stored, under row-level security, with a retention window enforced
by a scheduled purge.

**Rate limiting lives in Postgres**, not in process memory. A module-level
counter resets on every serverless cold start and is not shared between
concurrent instances, which means it does not limit anything.

## Stack

Next.js 16 (App Router) · TypeScript · Supabase (Postgres + Auth) ·
Groq (Llama 3.3 70B) · Tailwind CSS v4 · unpdf

## Getting started

See [SETUP.md](./SETUP.md).

```bash
npm install
cp .env.local.example .env.local   # fill in your keys
npm run test                       # 78 assertions, no network required
npm run dev
```

## Limitations

- Programme requirements in `data/programmes.json` are a seed set of eight
  programmes and carry a `lastVerifiedOn` date. Universities change entry
  requirements; re-verify before relying on a verdict.
- GPA conversion between Indian and 4.0 scales is approximate and is always
  disclosed alongside the original value. Several universities require a WES or
  ECE evaluation and will not accept any self-conversion.
- Scanned image PDFs are rejected. There is no OCR path.
- Name detection during redaction is heuristic. An unusual resume layout may
  leave a name unredacted.
